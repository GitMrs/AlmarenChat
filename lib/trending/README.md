# 热榜后台调度

- 时区为 `Asia/Shanghai`，每天 **08:00** 和 **23:42** 各抓取一次全部启用源，并强制更新当天全网 AI 总结。
- 启动或 PM2 重启只安排下一个未来时点，不进行启动补抓，也不补执行停机期间错过的任务。
- 同一轮抓取最多并发两个源，保留请求间隔；如果定时器延迟超过一分钟，该时段跳过。
- 每个时段先以独占文件记录执行，再开始请求，防止多个 PM2 进程重复执行。状态文件位于 `data/trending/scheduler/YYYY-MM-DD/0800.json` 和 `2342.json`，包含开始时间、结束时间及结果。
- 已认领的时段不自动重试。进程中途退出可能留下 `RUNNING` 状态，下次启动仍只等待未来时点。
- `COMPLETED` 表示这一轮调度已返回，不保证每个源都获取了新数据；数据源失败仍可能使用旧缓存，总结失败会单独打印日志。
- 页面访问、手动刷新与后台定时独立。热榜数据仍按原有 **15 分钟缓存**规则更新，AI 总结仍使用原有缓存与手动刷新逻辑。
- 本地开发默认关闭调度；保留 `ENABLE_SCHEDULERS=true` 的显式启用方式。

部署时保留 `data/trending/`，多个 PM2 进程需要共用同一个工作目录。此变更不涉及数据库迁移。

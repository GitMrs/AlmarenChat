# 聊天归档公共代码

`chat-archive.mjs` 供小伴与单个 Agent 的自动、手动聊天归档使用。两边共用摘要提示词、来源和时间格式、条目清理、失败兜底、批次选择及原消息引用整理。`chat-archive-content.mjs` 保存公共内容规则；原有导出名称保留兼容，双方共用下方的召回策略。

新摘要以北京时间标注用户陈述、助理说法（未独立核实）和对话事件。模型摘要的来源或时间标记不合要求，或模型调用失败时，提取完整的用户陈述条目；不把助理建议或用户提问变成已确认事实，不截取半句话充当事实。摘要的格式检查不代表内容已获独立事实核验。

自动归档仍在未归档消息达到64条时触发。自动和手动每次最多归档48条，普通批次的原文总长度上限为24000字符；单条超长消息单独归档，模型输入保留其开头和结尾并标注中段省略，完整原文仍在消息表。归档摘要上限2000字符，按完整条目收录。手动归档至少保留用户选择的最近消息；超出本批上限的早期消息留待继续归档，返回真实的本次归档条数及剩余数量。

模型配置、模型调用是否可用、自动触发时机仍沿用原入口：小伴非本地模式的自动归档与两边手动归档可提供模型回调；Agent自动归档未提供回调时使用同一套确定性提取规则。归档阶段不新增模型调用，也不改变本地模式的模型请求去向。

数据库查询、权限、事务及并发处理、Agent成长复盘仍由原入口负责。小伴继续用消息关联字段保存原文关系；Agent继续用现有标签保存消息ID及时间。历史归档表、旧摘要和任务/学习/空间活动归档保持原状。下述会话承接状态使用独立新表。

## 统一召回

`memory-recall.mjs` 负责双方共同的关键词提取、相关性排序、条目级聊天摘要选择、日期匹配、去重和上下文长度控制。两边长期事实记忆共用同一个筛选器；聊天归档共用同一个条目筛选器。Agent工作规则和任务/学习/空间经历保留类型边界，并复用公共相关性筛选。未命中具体主题时不以无关的最近记忆填充；明确回顾近期经历等宽泛请求可返回有限近期记录。

候选记录在数据库中先按关键词过滤，再应用条数限制，避免先截取最近几十条导致较早相关记录完全无法参与筛选。日期查询按北京时间解释；聊天归档结合起止时间筛选。Agent旧归档的起止时间和消息ID从既有tags中读取。每次预加载候选有上限，注入最多4个聊天归档、每份最多4条相关内容，总计最多4000字符；未命中不等于历史中不存在。

小伴和Agent仍分别查询各自的数据表，不共享私人记忆。Agent主会话传入当前会话范围；空间中不增加私人聊天原文读取能力。后台worker也使用公共筛选规则，并在SQL中先筛选相关候选。

## 有限原文回查

`memory-store.ts` 提供受权限约束的搜索与读取。`memory-tools.ts` 将其封装为只读的`memory_search`、`memory_read`工具，接入小伴和单个Agent的网页服务端及QQ聊天。现有模型工具循环可以先搜索归档ID，再读取原文；仅在真正调用工具时增加相应模型轮次，不依赖联网搜索，也不把记忆结果标成网页来源。

- 每轮最多4次记忆搜索、3次原文读取。
- 每个搜索候选页最多120份归档，每次返回最多4份匹配结果；按返回的nextPage、nextOffset续查，不能把未展示结果当作不存在。
- 每次原文读取最多6条消息、每条最多1200字符。offset继续翻消息页，messageId与contentOffset继续读取同一长消息。原文明确标注分页、截断及剩余状态。
- 已在近期上下文中的消息不重复提供；同一工具实例不重复返回已读过的同一消息片段。
- 每次读取都重新验证当前用户、Agent、主会话及存档归属。Agent还要求经历为ACTIVE、ACCEPTED、CHAT；原消息必须属于该会话且出现在存档关联中。不能通过工具参数更换身份或读取其他空间/角色原文。
- 旧归档没有原消息关联、源消息已经不存在或查询失败时明确报告，不能用猜测补充。

双方的上下文加载器还对明确追问历史原话、金额、时间、约定等问题自动补充一小段相关原文，因此浏览器本地模型也能获得原文依据。本地浏览器模型目前没有新增主动工具循环，按需主动搜索/读取工具由服务端模型使用；本地模型请求仍由浏览器发出。临时会话不因此读取长期聊天归档。

历史原文作为引用数据提供，保留说话人和时间；其中的指令不得作为本轮指令执行，助理原话不升级为用户事实。摘要和原文都不是现实状态的自动证明。

## 验证

测试使用隔离仓库、内存SQLite和模拟模型工具流，不需要启动应用或访问真实模型。覆盖两边选择一致、旧记录参与检索、日期与旧tags兼容、跨用户/角色/临时会话拒绝、原文分页与长消息续读、次数上限与去重，以及搜索→读原文→基于证据回答的完整工具链。


## 近期原文与会话承接

近期原文窗口与历史归档分别管理。小伴固定默认最多60条历史消息（不是60轮，当前输入另计一次），不再受账号的Agent历史条数配置影响；单个Agent沿用当前会话/账号可配置的1～80条上限，网页、QQ、本地浏览器路径一致。近期窗口从完整会话的用户/助理消息中选取连续末尾区间，不再根据assistantExperienceId或Agent归档游标排除原文。64/48仍只是历史归档处理参数。

`conversation-context.ts`统一准备聊天请求，`conversation-context-policy.mjs`负责连续窗口、Token估算和预算拼装。近期窗口尽量从完整用户轮次开始；条数是上限，受预算限制时可少于设置值。最新输入单独加入一次，已保存的当前用户消息仅通过明确的消息ID排除重复，重试入口先确认复用的当前消息；相同文字的新消息不会被当作重复。图片输入也参与预算估算。

退出近期窗口的前缀由独立的`ConversationContextState`承接，记录summary、throughMessageId、throughCreatedAt、sourceCount、version。每次只处理边界新增的消息；增加近期条数时，重建更早的正确交接边界。归档状态变化不会突然把60条近期原文变成16条。原文删除或清空时清除承接状态；边界消息不存在或前缀数量变化也会使旧状态失效。

承接记录优先保留明确用户限制、当前目标、最新进度，并区分助理提议与用户确认。较短内容直接按说话人、时间和消息ID摘录追加，不每轮调用模型。累计内容超过6000字符才整理：服务端在线模式可生成不超过4000字符的结构摘要，检查五类字段及真实来源ID；模型失败或格式无效不提交新边界。浏览器本地模式只使用有明确省略标记的摘录，服务器不代调在线模型。处理条数只表示摘要的来源范围，不保证所有细节保留；细节仍可回查原文。

会话状态只在当前用户的当前会话使用，临时会话的承接也不会变成长久经历或注入其他会话。乐观版本检查防止较慢请求覆盖另一请求的新状态。新表独立于聊天消息，不会作为聊天消息显示，也不会混入历史经历召回。

## 完整请求预算及透明度

预算基于已配置的模型窗口和现有回复预留策略估算；初始拼装为工具往返留出空间。必需角色/时间规则、当前输入、会话承接与连续原文优先，相关记忆、历史回查、知识库、平台背景按可用空间加入。因预算未加入的资料会记入manifest，同时告知模型不能声称已经读取。图片按保守固定值估算，实际提供方计费Token可能不同。

每轮服务端模型请求会重新计入工具schema、历史tool_calls及工具结果。超出含回复预留的窗口输入上限时明确停止，不静默删除当前消息，也不拆开工具调用和结果。本地浏览器请求也在发出前复核完整输入预算。

上下文面板分别显示：未归档进度、近期原文候选、历史归档、会话承接边界，以及最近一次请求拼装中的原文条数、摘要处理范围、完整输入估算和已加入/省略资料。准备记录不代表模型已经接收，请求阶段记录也不代表回复已完成。小伴输入框的条数徽标显示近期原文候选，不再把未归档条数当成实际上下文。

# 2026-11-01 触碰与换装互动对比

范围：官网公开页面脚本、公开台词索引，以及本地 Nari / Sunny、Yume / Cora 的事件、动作、表情和语音链。仅静态检查，没有启动页面、改变运行代码或生成音频。

## 官网证据与限制

检查的页面入口是 <https://nariyume.com/app/>。当期构建引用：

- `main-DRpSKB8d.js`：指针分类、recoil、语音选择、换装事件。
- `tapRegionLines.generated-CwHvXgJZ.js`：两位角色各有 head/face/body/spam/hold 五类英文文案，每类 8 条，共 80 条。
- `nativeVoiceIndex.generated-Bw8xmecN.js`：包含角色通用 Tap / Drag / StartupGreeting / TapEvent 等条目；**没有 TapHead / TapFace / TapBody / TapSpam / TapHold 条目**。

分区对白路径会尝试加载对应分类，缺失时会回退通用 Tap；还可按概率优先选 TapEvent。出现分区分类或英文文案，不代表相应中文专属配音已经在当前构建正常使用。未登录执行真实交互、未检查后台，不能确认所有线上模式的实际行为。

这也说明此前只比较通用 375 条台词，并不能代表完成了整个触碰体验的对比。对齐应以事件到最终反馈的实际链路为单位。

## 本地具体问题

### 1. 皮肤普通点击与连击没有分开

`CompanionPreview.tsx` 的 `selectTapLine(kind)` 在存在皮肤 tapLines 时，tap 和 rapid 都从同一个皮肤池抽取，kind 没有改变选词。达到五连击后又调用角色级 `getSurrenderReaction`，不再考虑当前皮肤。

### 2. 求饶反馈存在字幕/声音绑定问题

- Nari 行为配置的求饶字幕为“呀~ 投降啦，真的好痒呀！”，绑定 `tap_09.mp3`；该音频清单的文字为“好啦好啦，手下留情嘛~”。清单已能证明绑定的元数据不一致，尚未逐句听音确认实际录音。
- Yume 求饶条目没有 audioUrl，按现有 playVoice 路径只走字幕/口型时长模拟，不产生这条专属预录声音。

### 3. 换装亮相可能被聊天回复阻塞

播放入场/换装的 effect 在处理 `pendingEquipLineRef` 前，先以 `if (!ready || isStreaming || reply) return` 返回。reply 是已存在的回复对象，未限于“当前仍在播放”。因此存在已有回复时换装语音无法被消费的路径；需要交互回归确认，不应直接按注释认定每次换装都正常播出。

### 4. 换装表情 ID 无效

换装调用传入 `targetExpression: '开心'`。Nari / Yume 资源使用 Blushing、Shy 等表情 ID，playVoice 会检查 ID，找不到则回到自然表情，因此这里不能稳定产生注释所说的开心表情。

### 5. 点击位置没有角色命中判断

`handleCharacterTap` 只判断是否点击 canvas，没有排除画布中的空白，也没有把位置转换为角色部位。增加部位功能前，要处理半身/全身/特写和 PC/H5 镜头变化，不能用固定屏幕高度简单切三段。

## 建议的实施顺序

1. 先修复现有绑定：字幕和音频一致；求饶反馈明确；换装队列不被旧回复阻塞；使用真实表情 ID。暂不重录整套语音。
2. 再抽出统一事件：tap、rapid、hold、drag、equip，附带角色、皮肤和部位；先实现角色范围命中与头/脸/身体分类，兼容镜头和屏幕尺寸。
3. 只挑一套皮肤试改，配置每事件的成套字幕、声音、动作、表情及冷却。没有对应录音时明确降级，不用另一句录音配新字幕。
4. 验证单击、连击、长按、拖动释放、空白点击、播放中点击、已有聊天后换装和切换角色；PC/H5 各验收一次。
5. 感知差异确实成立后，再推广到其他皮肤，按缺失的具体事件少量补录 Fish。

- Nari 求饶字幕与已有 `tap_09.mp3` 清单一致；Yume 保护反馈使用已有 `tap_03.mp3` 及对应“别戳我啦”字幕。
- 8 套非经典原版皮肤增加 `interaction.tapReactions`，以原 tapLines 的索引区分普通点击、连击和保护反馈。文件序号保持不变，不新增文案或录音。保护反馈保持当前皮肤，不回退另一套角色录音。
- 换装语音独立排队：不再被历史 reply 对象永久阻塞，等待聊天流、当前语音和通话结束。快速切换皮肤、返回经典原版会取消过时的排队反馈。
- 换装复用角色有效的 happy 动作/表情映射，不再传无效的“开心”资源 ID；Yume 的 happy 主要由动作表达，允许自然表情。

新增音频绑定测试及界面事件回归，覆盖字幕和文件对应、旧回复后换装、快速换装、流式回复期间等待、当前皮肤连击/保护反馈及返回原版取消队列。未启动服务、构建或实际浏览器验收。

## 随后的第二轮修复

- 为 Nari / Yume 的 Koro 舞台增加 `hitTest(clientX, clientY)`，使用当前渲染相机矩阵、动态网格三角形及透明度判断命中，包含 zoom、半身/全身/特写、相机插值、键盘挤压和模型纵向平移的坐标处理。只在指针事件中计算命中，不逐帧遍历碰撞三角形。
- 命中后，在模型坐标中依据模型总高度划分 head / face / body，分别使用不同的现有录音池与动作/表情映射。分区配置位于 `interaction.touchLines`，按 tapLines 原索引绑定字幕与音频；经典原版从基础 Fish 录音中选择对应池。
- 按住至少 700ms、未进入拖动且释放时仍命中角色，触发 hold 反馈；合格的移动手势仍进入拖动，不同时播放长按。释放后的合成 click 不重复播放。长按不会打断正在播放的语音，也不会积累连击。
- 空白起按后移入角色不转成点击。角色范围外不触发新对白或跟随。保留功能按钮隔离和已有连击冷却，防止拖动释放误触单击。
- 为角色画布抑制原生长按菜单，保留 H5 指针手势。未改变其他 Cubism 角色的交互规则。
- 不新增、重录或上传音频；已有皮肤录音的文本和文件保持一一对应。针对具体部位不具备专属说辞时使用已有的合适反馈，不给另一句录音配新字幕。

精度边界：角色范围依据可见网格几何，未逐像素采样贴图 alpha 或重算裁剪遮罩；透明贴图的边缘可能仍有少量可点范围。头/脸/身体为模型坐标中的近似解剖分区，不是骨骼语义标注。换装后夸张姿态的部位边界及 PC/H5 手感仍需实际页面验收。

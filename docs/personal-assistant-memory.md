# 个人助理会话与记忆

本文档记录个人助理主聊天、临时聊天和分层记忆的当前行为。代码与测试是行为的最终依据；本文档用于说明产品规则、模型调用、数据迁移和后续演进边界。

## 会话模型

每个用户拥有一个不可删除的主聊天，并可以在网页端创建多个临时聊天。

| 会话 | 网页 | QQ | 自动经历 | 长期事实 |
| --- | --- | --- | --- | --- |
| 主聊天 | 默认进入 | 与网页共用 | 参与 | 可以提出待确认建议 |
| 临时聊天 | 用户主动创建 | 不使用 | 不参与 | 不自动提取 |

具体规则：

- `PersonalAssistantProfile.conversationId` 始终指向用户的主聊天。
- 主聊天使用 `Conversation.assistantMode = MAIN`，临时聊天使用 `TEMPORARY`。
- 打开或切换临时聊天不会修改主聊天指针。
- 主聊天不能删除，只能清空消息；临时聊天可以删除。
- 原有 QQ 独立会话保留为临时历史，不合并或覆盖原始消息。
- `AssistantQQBinding` 指向主聊天；QQ 后续消息与网页主聊天使用同一时间线。
- 消息通过 `Message.source` 标记为 `WEB`、`QQ` 或 `SYSTEM`。

## 三层记忆

个人助理当前使用三层上下文，而不是把全部历史消息原样发送给模型。

### 近期原始消息

- 保存网页和 QQ 主聊天中最近尚未归档的原始消息。
- 每次请求仍受用户的 `contextMessageLimit` 限制，当前范围为 8 至 80 条。
- 临时聊天只读取自身最近消息，不读取主聊天经历。

### 自动经历

- 主聊天累计 64 条尚未归档的用户或助理消息时，归档最早的 48 条。
- 每次归档后至少保留 16 条近期原始消息，之后每新增约 48 条消息再归档一次。
- 在线模型把一个批次压缩为 300 至 800 个中文字符的经历摘要。
- 摘要请求最长等待 20 秒；模型失败、超时或使用浏览器 Ollama 时，改用确定性摘要，避免阻断聊天或反复消耗调用。
- 原始消息不会因归档而删除，只会关联到对应的 `AssistantExperience`。
- 每次主聊天请求最多装载 12 段经历，包括最近经历和按当前问题做文本相关性匹配的经历。
- 设置页的“自动经历”会显示最近 20 段摘要；用户可以按需展开查看对应原始消息。

自动经历是对聊天轨迹的压缩，可能省略细节。它不能覆盖用户确认的长期事实，也不能覆盖较新的原始消息。

### 用户确认的长期事实

- `AssistantMemoryItem` 保存用户确认过的偏好、习惯和背景事实。
- 普通问答不调用长期事实提取模型。
- 只有用户明确说“请记住”，或表达稳定个人信息，例如“我平时喜欢”“我习惯”等，才生成待确认建议。
- 用户可以在助理设置中添加、停用或删除长期事实。
- 临时聊天不会提出长期事实建议。

## 模型上下文

网页主聊天和 QQ 主聊天按相同顺序构建主要上下文：

1. 助理身份、Soul、当前时间和平台使用规则。
2. 用户确认的长期事实。
3. 与本轮相关的自动经历和最近自动经历。
4. 用户允许读取的平台活动摘要。
5. 尚未归档的近期原始消息。
6. 当前用户消息。

联网搜索仍由本轮联网开关单独控制。记忆检索只读取本地 SQLite 数据，不会触发联网。

## 删除与清空

- 清空临时聊天只删除该临时聊天的消息。
- 清空主聊天会删除主聊天原始消息和由它们生成的自动经历。
- 清空聊天不会删除用户确认的长期事实、待办或提醒。
- 删除一条已归档消息时，对应经历摘要会失效并删除；同批次剩余原文恢复为未归档状态，之后可以重新生成正确摘要。
- 删除临时聊天后返回主聊天，不改变主聊天内容。

## 数据结构

主要字段和模型：

| 数据 | 用途 |
| --- | --- |
| `Conversation.assistantMode` | 区分主聊天和临时聊天 |
| `Message.source` | 区分网页、QQ 和系统消息 |
| `Message.assistantExperienceId` | 关联原始消息和经历摘要 |
| `AssistantExperience` | 保存摘要、消息数量和起止时间 |
| `AssistantMemoryItem` | 保存用户确认的长期事实 |

`AssistantExperience` 同时关联用户和主聊天。读取经历原文的接口必须使用 `experienceId + userId` 鉴权，不能仅按经历 ID 返回数据。

## 部署升级

本次包含两个数据库迁移：

- `20260905090000_add_assistant_main_and_temporary_chats`
- `20260905120000_add_assistant_experiences`

兼容升级脚本 `scripts/upgrade-agent-runtime.mjs` 支持重复执行，并负责：

- 补齐主聊天、临时聊天和消息来源字段。
- 将旧 QQ Binding 改为指向主聊天，同时保留旧 QQ 会话。
- 创建经历摘要表、消息关联字段和查询索引。
- 修正同一用户可能存在的异常重复主聊天标记。

部署后需要重启 Web 服务和 QQ Worker。空间任务 Worker 没有新增职责，但生产环境仍应保持各进程使用同一版本代码。

## 当前边界

当前版本借鉴了 Alife 的“原文持久保存 + 分批压缩 + 可追溯”机制，但没有直接复制完整实现：

- 没有引入 DuckDB、向量模型或新的原生依赖。
- 没有进行经历摘要的递归多级压缩。
- 文本相关性检索基于近期范围和关键词，不是向量语义检索。
- 自动经历不会自行升级为用户长期事实。
- 经历归档发生在后续一次主聊天请求开始前，不依赖定时任务。

只有当经历数量和检索质量证明有必要时，再考虑 SQLite FTS、二级摘要或可替换的向量检索层。不能为了形式接近 Alife 而增加当前部署环境不需要的原生依赖。

## 代码入口

- `lib/personal-assistant/experience-memory.ts`：归档阈值、摘要生成、并发保护和上下文检索。
- `lib/personal-assistant/memory-intent.mjs`：长期事实建议的低成本前置判断。
- `lib/personal-assistant/prompt-builder.ts`：三层记忆的系统提示结构。
- `app/api/assistant/messages/route.ts`：网页消息接入、归档和清理语义。
- `app/api/internal/assistant/qq/messages/route.ts`：QQ 主聊天接入和归档。
- `app/api/assistant/experiences/[experienceId]/route.ts`：鉴权读取经历原文。
- `components/assistant/PersonalAssistantSettings.tsx`：长期事实和自动经历界面。

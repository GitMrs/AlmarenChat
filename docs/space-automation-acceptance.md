# 空间自动化端到端验收

以下验收不依赖本地历史数据库，可在新环境创建一个公众号创作室完成。数据库升级前先备份生产 SQLite 文件。

## 前置条件

- 空间类型为“公众号创作室”，至少有一名可执行成员。
- 微信公众号连接器已保存 AppID/AppSecret，并完成连接验证，状态为 `READY`。
- Worker 与 Automation Worker 均使用升级后的同一数据库。

## 主流程

1. 创建每日或每周自动化，选择“每次新建成果”“定稿后准备微信草稿”和一个排版主题。
2. 任务要求明确生成一篇可发布 Markdown 正文，以及一张属于同一成果、文件名包含 `cover` 或“封面”的图片。
3. 手动立即运行一次，确认只创建一个自动化执行和一个新的 `SpaceWork`。
4. 执行成功后确认成果进入“待定稿”，页面出现“确认定稿”动作，微信草稿尚未创建。
5. 批准定稿，确认成果变为“已完成”，并立即出现独立的“确认创建草稿”高风险动作。
6. 批准创建草稿，等待 Worker 完成，确认发布记录中出现草稿 ID，并出现新的“确认正式发布”动作。
7. 在微信后台核对草稿正文、封面和主题。未批准正式发布前，文章不得对外发布。
8. 批准正式发布，等待微信处理完成，确认发布记录保存发布 ID、文章 ID 和最终链接。
9. 打开“运营概览”，确认草稿数、正式发布数、待审批数和自动化成功率与本次执行一致。
10. 发起下一次空间任务，确认 Coordinator 的空间记忆包含本次草稿创建或正式发布结果。

## 失败与安全边界

- 同一成果没有 Markdown、存在多篇 Markdown、没有图片或多张图片且未唯一标记封面时，定稿仍然成功，但不得创建草稿审批；聊天中应显示手动处理原因。
- 连接器不是 `READY` 时，定稿仍然成功，但不得调用微信 API。
- 修改已经进入草稿审批的正文或封面后再批准，Worker 必须因哈希不一致而失败。
- 草稿创建完成后不得自动正式发布；正式发布必须拥有另一条独立审批记录。
- 重复提交同一个定稿审批不得产生第二条草稿动作。
- 外部写请求期间 Worker 中断时不得自动重放，动作应标记为结果未知或失败并提示人工核对。

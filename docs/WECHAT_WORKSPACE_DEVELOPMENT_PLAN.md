# 微信公众号专用工作室开发计划

建立日期：2026-11-09。

状态：2026-11-10 一期本地开发与验收完成。阶段 0～6 的本地检查已完成；独立生产构建、123 项测试、类型检查、最新 HTTP 以及桌面和手机页面复验通过。真实微信互通、微信编辑器粘贴和模型写作质量未实测，未部署、未升级实际数据库。完成范围和限制见第 6 节证据表及下方最终记录，不能据此宣称真实微信全链路验收完成。

调研依据：[公众号工作室需求调研](./WECHAT_WORKSPACE_RESEARCH.md)。本计划与能力商店计划分别管理。

## 1. 目标与范围

新增专门服务微信公众号的工作室入口和页面，以账号定位、选题、文章、素材与发布组织使用流程，减少对通用功能模板的依赖。

保留并复用现有成员、角色、聊天上下文、记忆、Task、工作区、成果、版本、审批与自动化。闲聊和 Task 仍是两条线路，讨论不自动变成任务，制作或修改产物沿用既有确认机制。

严格范围：

- 只实施公众号相关功能，不重构普通空间、合约、Bilibili、Studio 或单 Agent。
- 不实施统一能力商店，不顺带开发第三方 MCP、CLI 和其他平台接入。
- 共用文件允许做公众号接入所需的最小改动；其他空间默认路径和行为必须保持不变。
- 不复制通用空间整页和整套聊天、任务后端，也不借此重构整个空间框架。
- 不自动覆盖旧空间的自定义规则，不移动或删除已有内容。

## 2. 实现原则与工作假设

以下是用于推进开发的建议基线；新发现导致调整时，在本文记录原因和影响，不悄悄扩大范围。

1. 专用页面仍关联现有 Space，文章仍对应 SpaceWork，文件保留现有路径和成果隔离机制。
2. 公众号业务识别与写作模板分离。按 2026-11-10 用户最新要求，统一从“新建空间”选择“公众号文章”模板进入；不在空间列表平铺专用创建按钮。该选择映射到公众号业务类型和新默认规则，不恢复旧模板强制流水线；旧 `templateId=wechat-article` 保留兼容。不引入新的执行引擎或通用插件框架。
3. 页面路由可以独立，最终命名在阶段 0 固定。用户可从空间列表进入公众号工作室；原链接仍能访问或定位到同一空间。
4. 一期不强制绑定微信公众号账号。未连接时可完成创作、预览、复制；连接后按实际权限使用草稿和发布。
5. 账号定位保留 `shared/content-strategy.md` 为现有兼容来源，不同时维护相互矛盾的两份定位。若增加编辑表单，必须明确写回方式和并发处理。
6. 文章级需求、修改意见与发布字段先核对已有 objective、文件、版本和快照能力，优先复用；只有现有结构无法表达时增加最小字段。
7. 写作风格由账号定位、本篇要求和当前角色决定。文件契约、事实和权限约束保留；固定首句、段长、爆款标题数量改为方法建议，不再强制所有文章一致。
8. 用户本轮要求优先于默认方法；Skill 不改变 Agent 身份，也不扩大联网、脚本或外部发布权限。

## 3. 一期页面与业务闭环

| 区域 | 一期内容 | 边界 |
| --- | --- | --- |
| 对话 | 保留成员与 @、讨论选题、反馈、发起或继续 Task、显示运行状态 | 不新增一套对话历史和记忆 |
| 当前文章 | 展示左侧选中成果的本篇需求、正文、发布资料、修改和现有版本入口；没有选中时显示空状态 | 新建和切换复用左侧入口，不重复提供列表和创建表单 |
| 素材 | 当前文章和空间公共资料、来源、封面与正文图 | 不混用其他文章的私有素材 |
| 发布 | 发布前检查、排版预览、手动复制、草稿审批、正式发布审批、发布记录 | 不把发布等同于群发通知 |
| 账号设置 | 定位、风格、连接状态、现有空间设置入口 | 不重写全站用户和账号系统 |

用户可以只讨论、导入已有文章、只改一段、只调整排版。定位、大纲、正文、封面不是每次都必须重新生成的完整流水线。

## 5. 代码落点与改动约束

### 阶段 0 已确定的落点

- 专用地址：`/wechat/[spaceId]`。复用既有页面控制器，在公众号中展示独立文章中心；不复制整套聊天和任务实现。旧 `/spaces/[spaceId]` 公众号链接定位到同一空间的专用地址并保留查询参数。
- 业务识别：`Space.workspaceType`，默认 `GENERAL`，公众号为 `WECHAT`。统一通过 `isWechatWorkspace` 识别；旧 `templateId=wechat-article` 仍有效。创建弹窗选择公众号模板后提交 `workspaceType=WECHAT`、`templateId=null`，将模板选择作为用途入口，新工作室不保存旧流程快照；现有生命周期在无快照时已有默认阶段。
- 迁移：`20261109090000_add_wechat_workspace_type`；只增加字段并标记旧公众号，保留所有其他字段。运行时升级脚本补同一字段及迁移识别，需在服务启动前升级数据库和生成 Prisma Client。
- 数据来源：定位沿用 `workspace/shared/content-strategy.md`；本篇需求用 `SpaceWork.objective`；正文、发布资料、图片归属对应 Work；人工修改沿用文件编辑和 SpaceWorkVersion。结构化发布字段保存在 `SpaceWork.metadata.wechatPublishing` 并冻结到审批快照；`publish-info.md` 继续承载备选标题、来源等说明，实际提交字段以表单为准。
- 配置优先级：用户本轮明确要求和修改意见、本篇已确认需求、账号定位、默认写作方法；现有定稿及发布审批快照不随配置变更自动改写。
- 历史 PI_CODING 空间保留既有聊天入口和执行方式，不因专用地址悄悄转成另一执行引擎。实际浏览器与 HTTP 已验证原聊天界面、规则及 pi 执行标识保留；该历史分支沿用原功能，不提供新的多文章中心，不将其悄悄迁移到 Work 执行。

## 6. 最终验收场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| W01 | 新建公众号工作室 | 从统一“新建空间”选择公众号模板，创建后进入专用页面，基础聊天、成员和文章功能可用 |

| W05 | 导入已有文章并局部修改 | 使用原稿，只修改要求范围，用户可查看与恢复已有版本 |
| W06 | 切换文章／刷新／任务运行中编辑 | 当前对象清楚；不跨文章写入，不静默覆盖未保存修改 |

| W08 | 标题超限、HTML 超限、图片缺失 | 发布前明确阻止并定位原因，不静默裁剪 |
| W09 | Token 有效但发布无权限 | 不误报所有功能就绪；失败可解释，可手动复制 |
| W10 | 创建草稿并正式发布 | 两次独立确认；素材冻结；查询到最终成功才展示已发布 |
| W11 | 拒绝审批、修改素材、Worker 中断 | 不绕过审批、不发布未确认内容、不自动重放结果未知请求 |
| W12 | 原有公众号自动化及执行引擎 | 已声明支持的 native/pi 和历史聊天分支继续可用；不悄悄迁移执行方式 |
| W13 | 其他空间回归 | 普通、合约、Bilibili 的创建、对话、专用面板及任务保持原行为 |
| W14 | 权限与升级 | 跨用户访问拒绝；旧库升级可用，升级后历史数据完整 |

# 空间模板

空间模板用于快速建立面向轻量数字交付的协作空间。模板不是新的角色系统，也不创建另一套任务运行时。

## 概念边界

- Agent：现有的协作成员，定义身份与专业能力。
- Skill：Agent 在任务中可以使用的工具和执行能力。
- 空间模板：创建空间时采用的一组 Agent、工作规则、推荐流程和交付物预设。
- Coordinator：继续使用现有 V3 Runtime，根据用户当前目标决定直接回复、单成员执行或多成员协作。

模板流程只提供默认方法。空间规则明确要求简单任务不得机械执行全部阶段，用户当次要求始终优先。

## 内置模板

当前内置以下模板：

1. 公众号文章
2. 网页制作
3. 短视频脚本
4. 剧本与小说
5. 调研报告
6. 方案策划
7. 产品需求文档
8. 课程与培训资料

模板定义位于 `lib/space-templates.mjs`。每个模板包含稳定 ID、版本、推荐 Agent、推荐 Skill、工作流程、默认交付物、质量规则和开场示例。

## 创建和持久化

用户从模板创建空间后仍可调整名称、规则、成员及其顺序。服务端只接受平台注册的模板 ID，并使用服务端模板生成快照，不能由客户端伪造模板内容。

`Space` 保存三个模板字段：

- `templateId`：内置模板稳定 ID。
- `templateVersion`：创建空间时采用的模板版本。
- `templateSnapshot`：创建时的流程、交付物、推荐 Skill、实际成员和开场示例。

实际执行规则仍保存在 `Space.instructions` 中，现有聊天和任务运行时无需新增分支。模板以后升级时，旧空间继续保留创建时快照和用户已经修改过的空间规则。

## 一个空间中的多个成果

空间是长期工作室，不需要为每篇文章、每份报告或每个页面重复创建。每次在“新建成果”模式确认任务方案时，系统创建一个通用 `SpaceWork`；后续可在输入区选择已有成果继续修改。

Agent 仍使用 `article.md`、`index.html` 等简洁逻辑路径，平台在磁盘上隔离保存为 `workspace/works/{workId}/...`。因此不同成果可以拥有同名文件，不会相互覆盖。任务重试继续使用原 Work，不会生成重复成果。

旧版本位于空间根工作区的文件不会自动搬迁或删除，在界面中归入“公共资料 / 历史成果”。

### 公众号文章 V2

公众号模板将发布正文和编辑资料分开交付：`article.md` 只包含唯一正式标题与正文，`publish-info.md` 保存备选标题、摘要、封面建议、来源和核验说明。空间文件编辑器会把 Markdown 渲染为带内联样式的发布预览，并可通过“复制到公众号”写入富文本剪贴板；旧版文章前置的备选标题与摘要会在复制时自动排除。发布预览内置简约黑白、清新绿和商务蓝三种主题，主题选择保存在当前浏览器中，预览与复制始终使用同一套样式。发布按钮只显示在正式文章文件上，发布资料、README、来源清单、大纲、素材和草稿仍可预览编辑，但不会被误识别为待发布正文。

## 部署

模板字段需要执行数据库升级。生产部署脚本已经调用 `yarn db:upgrade-agent-runtime`；手动部署时先运行该命令，再重启 Web 和 Worker。

对应 Prisma migrations：`20260906090000_add_space_templates`、`20260906150000_add_space_works`。
